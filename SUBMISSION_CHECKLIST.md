# DECO3500 final submission checklist

Use this checklist against the course brief. **Do not tick an item until it exists and works.**

## Week 12 interactive tradeshow
- [ ] Prototype supports meaningful interaction and **multiple users**.
- [ ] Someone outside the team can use the prototype unassisted.
- [ ] Prototype can be demonstrated reliably in studio.
- [ ] A2 portrait (420 × 594 mm) conference-style poster is ready.
- [ ] Every team member can deliver a 2–3 minute pitch.
- [ ] Poster/promo materials are linked from the main README.

## Week 13, Monday 3pm — submission
- [ ] Public GitHub repository link submitted to Blackboard.
- [ ] README provides navigation and precise demo/deployment instructions.
- [ ] Source code/prototype is accessible from the repo root or linked.
- [ ] Research, requirements, design iterations, evaluations and evidence are uploaded.
- [ ] GitHub Projects shows issues/task tracking.
- [ ] Internal stand-up records are published **on GitHub Wiki**, not only in `wiki-import/`.
- [ ] `Design Process Overview` Wiki page published (~1,000 words + images, excluding references).
- [ ] `Ethical Considerations` Wiki page published with an ethics framework.
- [ ] Both required Wiki pages exported to one PDF named `TeamName_3DesignPrototype.pdf` (replace TeamName with your actual team name).
- [ ] Wiki publicly accessible or access confirmed for staff.
- [ ] Final README links correct and content reflects the actual deliverables.
- [ ] No personal details, unconsented photos or raw identifiable interview data posted publicly.

## Evidence quality self-check
- [ ] Research insight claims include citations or anonymised quotes.
- [ ] Every important design change links to testing evidence.
- [ ] Social/mobile theory and trade-offs are explained.
- [ ] Who did what is clear and accurate.
- [ ] Setbacks, limitations and critical reflection included.
